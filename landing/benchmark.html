The method

Certain answers.
No grading on a curve.

Each target has planted, known vulnerabilities — so recall and false-positive rate are measured against truth, not estimated. The suite spans local labs and authorized public test sites.

Suite 01 · Local lab

Planted bugs

A black-box web + API lab with known SQLi, XSS, SSTI, SSRF, IDOR, authz, CORS, LFI, NoSQLi and more — ground truth certain.

Suite 02 · Auth lab

Access control

Dedicated auth and authorization targets: BFLA, broken access control, and privilege boundaries under grey-box conditions.

Suite 03 · ASP.NET

Framework depth

A stack-specific target to prove the engine adapts its methodology to the framework it actually finds.

Suites 04–05 · Public

Authorized test sites

Industry-standard intentionally-vulnerable sites (vulnweb) used to validate against widely-known baselines.

Scoring

Recall + FP rate

Did it find the planted bug? Did it avoid crying wolf? Both are scored — a money-weighted, false-positive-penalized score.

Control

Deterministic mode

A no-LLM deterministic path makes core recall reproducible run to run — the same inputs give the same measured result.
